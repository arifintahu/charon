## Code changes applied

Applied on 2026-05-17 21:45 +0700 in response to a deeper rugpull-detection investigation that re-ran the feature analysis over 14 days (202 rugs vs 92 winners). Root cause: tightening existing entry counters (`smart_degen_count`, `hot_level`, holder concentration) was whack-a-mole — those features are sybil-fakeable and show identical distributions on rugs vs winners. The real separators are structural: **liquidity depth** (rugs at p25 = $13.4k vs winners at p25 = $15.7k) and **mcap-to-liquidity ratio** (rugs p25 = 2.02 vs winners p25 = 2.34). A rugpuller can fake organic-buyer counts cheaply, but cannot fake real SOL in the pool without surrendering the rugpull. Also discovered three dead filters that have never fired in the cohort.

#### `src/pipeline/candidateBuilder.js` — new filter checks

Added after the existing market cap block:
```js
// Liquidity floor — gap-through SL protection
if (strat.min_liquidity_usd > 0 && liquidityUsd < strat.min_liquidity_usd) {
  failures.push(`liquidity: ${liquidityUsd} < ${strat.min_liquidity_usd}`);
}

// Mcap/liquidity ratio — thin runners with disproportionate liquidity rug under any sell pressure
if (strat.min_mcap_to_liquidity_ratio > 0 && liquidityUsd > 0 && Number.isFinite(mcap)) {
  const ratio = mcap / liquidityUsd;
  if (ratio < strat.min_mcap_to_liquidity_ratio) {
    failures.push(`mcap/liq ratio: ${ratio.toFixed(2)} < ${strat.min_mcap_to_liquidity_ratio}`);
  }
}
```
