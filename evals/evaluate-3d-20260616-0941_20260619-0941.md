## Code changes applied 2026-06-19

Acting on recommendation #1 (breaker over-suppressed on a no-crash window). Two changes: (a) the breaker trip threshold was raised 3 → 4; (b) the breaker cooldown was made per-strategy configurable via `strategies/*.json` so the lever lives with the strategy it governs instead of only in global `settings`.

### 1. Cooldown is read from the active strategy (`src/pipeline/orchestrator.js`)

Precedence: **strategy JSON > global setting > code default** — matching the existing `strat.llm_min_confidence ?? numSetting(...)` pattern already in this file. The `sl_cooldown_until_<id>` expiry timestamp stays in `settings` (runtime state, not config).

```js
// before:
function checkSlCooldown(stratId) {
  const key = `sl_cooldown_until_${stratId}`;
  const threshold = numSetting('sl_streak_cooldown_count', 3);
  const cooldownMs = numSetting('sl_streak_cooldown_ms', 3600000);
  const until = numSetting(key, 0);
  if (Date.now() < until) return { active: true, armed: false, until, threshold, cooldownMs };
  const recent = recentClosedExits(stratId, threshold, Date.now() - cooldownMs);
  ...
}
// caller:
const cooldown = checkSlCooldown(strat.id);

// after:
function checkSlCooldown(strat) {
  const key = `sl_cooldown_until_${strat.id}`;
  const threshold = strat.sl_streak_cooldown_count ?? numSetting('sl_streak_cooldown_count', 3);
  const cooldownMs = strat.sl_streak_cooldown_ms ?? numSetting('sl_streak_cooldown_ms', 3600000);
  const until = numSetting(key, 0);
  if (Date.now() < until) return { active: true, armed: false, until, threshold, cooldownMs };
  const recent = recentClosedExits(strat.id, threshold, Date.now() - cooldownMs);
  ...
}
// caller:
const cooldown = checkSlCooldown(strat);
```

### 2. Two optional strategy fields (`src/strategy/schema.js`)

Optional (`required: false`) so strategies that omit them still validate and fall back to the global setting / default — the validator rejects unknown fields, so the whitelist had to allow them.

```js
// before:
  sl_arm_delay_ms:                   { type: 'number',  required: true },
};

// after:
  sl_arm_delay_ms:                   { type: 'number',  required: true },
  sl_streak_cooldown_count:          { type: 'number',  required: false },
  sl_streak_cooldown_ms:             { type: 'number',  required: false },
};
```

### 3. degen set to the tuned values (`strategies/degen.json`)

The trip threshold raised 3 → **4** (recommendation #1); cooldown left at 1h. degen.json is now the source of truth for this lever.

```json
// before:
    "sl_arm_delay_ms": 0

// after:
    "sl_arm_delay_ms": 0,
    "sl_streak_cooldown_count": 4,
    "sl_streak_cooldown_ms": 3600000
```

**Effect on the lever:** raising the count 3 → 4 means a 3-SL run on a choppy-but-recoverable day no longer arms the breaker — directly targeting the Jun 17 over-suppression (91 entries blocked on a −1.42% day). Cooldown duration unchanged. Per CLAUDE.md, strategy JSON is rebuilt into SQLite at boot, so this takes effect on the live bot after deploy + restart (or `/resetstrategies confirm`); until then the `numSetting` fallback already carries the live-tuned `count=4` set on 2026-06-19.

**Verification:** `npm run check` passes; `loadStrategiesFromDisk()` validates all four strategy JSONs and degen resolves `sl_streak_cooldown_count=4`, `sl_streak_cooldown_ms=3600000`. The breaker firing path itself is not verifiable headlessly (requires ≥4 consecutive live SLs); first real confirmation is the next window with a SL streak.
